# 测试接缝

这个仓库只有**两个**测试接缝。加断言时先想清楚属于哪一个 —— 不要新建第三个。

| | 接缝 | 跑在哪 | 管什么 |
|---|---|---|---|
| ① | **构建产物**（本目录，Vitest） | `out/`，无浏览器 | 导出了哪些文件、文件里写了什么、总共多大 |
| ② | **浏览器**（Playwright + Lighthouse CI，见 #66） | Cloudflare Pages 预览链接 | 只放**运行时才测得出**的：Core Web Vitals、reduced-motion、幕布转场不搞坏导航 |

**动效手感不进自动化。** 滚动惯性、逐行揭示的节奏、遮罩视差的速度只能真机看 —— 写断言说「视差感觉对」是纯浪费。

## 怎么跑

```bash
npm test        # 构建 + 断言（构建失败则整条命令失败）
npm run test:only   # 只跑断言，复用现有的 out/
npm run test:watch  # 改断言时用
```

## 怎么加一条断言

1. **先找现成的文件。** `export/assets.test.ts` 管资源，`export/hygiene.test.ts` 管「不该出现的东西」。
2. **`hygiene` 里加一条只需在 `FORBIDDEN` 数组加一行** —— 写上 `what` / `match` / `why`，`why` 要说清为什么，未来的人才知道能不能删。
3. **需要新数据时**，在 `helpers/export.ts` 里加一个派生字段，别改它的结构。
4. **新关注点开新文件**，放 `export/` 下。fixture 会被自动复用。

`helpers/export.ts` 只读文本文件（html / css / xml / txt / json / js）。`out/` 里有几百 MB 图片，**绝不要整包读进内存** —— 用 `sizes` 拿体积，用 `has()` 判存在。

## 两条特殊约定

**棘轮（ratchet）** —— 有些断言在对应的票做完之前不可能为 0。这类写成「不超过基线」，基线只允许降不允许升，并在注释里写明哪张票会把它清零。清零之后就把注释改成硬约束，别留着「基线」字样误导人。

> 用过一次：冗余原图的基线从 46 起步，#71 做完后归 0。中间那段时间它挡住了「又提交一张原图」的回退。

**已知缺失清单** —— 只放**已经有票在跟**的缺失项，且**必须配一条反向断言**：修好了却没从清单里删，测试同样会红。不要用它掩盖新问题。

> 这个约定已经救过一次：#81 把 `css/` 与 `js/` 移进 `public/` 之后，反向断言立刻报「这些已经不缺了，请从清单里删除」。没有它，那份清单会一直挂着，掩盖后续真正的缺失。目前清单是空的（实现已移除），需要时按这个模式重建。
