# 银行邮件改由 Gmail 转寄进来，不再经过 iPhone 自动化

> 状态：已实作。取代 ADR-0003 里「快捷指令转寄原文」那一段运送方式；ADR-0003 的其余决定（原文交给小帐本解析、认不得清单、卡片对应）不变。

## 背景

ADR-0003 让 iPhone 的「电子邮件」自动化把银行邮件 POST 进收件箱。实机跑起来之后：

- 自动化**会触发**，也送得到 Worker，可是「快捷指令输入」的「内容（Content）」是**空的**。寄件人、标题都有，正文没有，而金额与商家全在正文里，于是每一封都落进「认不得」。
- 在自动化里先「等待」5 秒再送，正文还是空的。自动化拿到的是触发那一刻的邮件物件，等多久都不会补上。推测是「邮件」app 那时只下载了信头（Gmail 账号尤其如此），没办法从快捷指令这一侧修。
- 设置本身也容易做错：三个字段要加在 `mail` 词典**里面**，加在外层就送出 `{"mail":{}, …}`；拿 ▶ 手动运行来测，输入一定是空的。

## 做法：Gmail 过滤器转寄 → Cloudflare Email Routing → Worker

```
银行寄出交易邮件
  → Gmail 收到，过滤器（寄件人 = 银行）转寄到 mb+<别名>@h2o-dreamer-studio.com
  → Cloudflare Email Routing：mb@ 这条规则（开了子地址）交给 Worker moneybook-inbox
  → Worker email()：认出别名 → 用 postal-mime 读出寄件人、标题、正文 → 当场用公钥封起来 → D1
  → 小帐本打开 → 拉取、解封 → parseBankMail()（跟以前一样）
```

- **每个收件箱一个转寄地址**：`POST /i/:id/mail`（要读钥匙）发一个 20 字 base32 小写的别名，库里只存它的 SHA-256（跟写钥匙一样）。再要一次就换新的，旧的随即失效。只用小写，因为邮件地址在路上可能被改大小写；Worker 比对前也先转小写。
- **一条规则接住所有人**：Email Routing 开子地址（RFC 5233）后，`mb@` 这一条规则就收得到每个 `mb+…@`，不必每开一个收件箱去加一条规则。
- **Worker 只把信读成文字**：寄件人用信头 From（Gmail 转寄时信封地址是 Gmail 自己），正文优先用纯文字部分，只有 HTML 时转成一行一行的文字（表格一格变空格、一列变一行，`Amount:` 跟金额才会同一行）。给小帐本的格式跟快捷指令投的 `{mail:{from, subject, body}}` 一模一样，**`ledger.js` 一行都不用改**。
- **限制与快捷指令那条路共用**：同一套截字（寄件人 200、标题 300、正文 8000）、待同步上限、每日上限。原文超过 256 KB 退信。认不得的地址、收件箱满了也退信：Gmail 会收到退信通知，使用者才知道这条路断了，而不是银行邮件静静消失。
- **Gmail 的转发确认信照样走这条路**：它进小帐本的「认不得」清单，标题里就有确认码，使用者抄回 Gmail。不必另外做一个收确认信的地方。

## Considered Options

- **继续修 iPhone 自动化**：「等待」无效，正文拿不到是 iOS 这一侧的事，没有可以改的地方。被否。
- **所有人共用一个固定地址，Worker 按寄件人猜是谁的**：转寄之后寄件人都是银行，分不出是哪个收件箱。被否。
- **只给一个人用的固定地址（环境变数写死收件箱 id）**：改得最少，但小帐本放在官网上给任何人用，第二个使用者一来就得拆掉重做。被否。
- **地址里直接放收件箱 id 加写钥匙**：43 字的写钥匙加 22 字的 id 超过邮件地址 local part 的 64 字上限，而且大小写敏感的 base64url 经不起转大小写。所以另发一个短的、全小写的别名。

## Consequences

- **Worker 第一次在加密前看到整封邮件的原文**（以前是快捷指令送来的三个字段）。隐私边界没变：原文只在内存里停留到封好为止，绝不写日志，库里只有密文。隐私页已补上 Email Routing。
- 需要 Cloudflare 那边做一次设定（子地址 + 一条规则），见 `workers/moneybook-inbox/README.md`。没设 `MAIL_DOMAIN` 时 Worker 不发地址，小帐本的按钮会显示失败。
- Gmail 过滤器只能在电脑版 gmail.com 建，设置步骤写明这一点。
- 只用别的邮箱（Outlook、Yahoo）的人一样能设转寄，但步骤只写了 Gmail。等有人要再补。
- 快捷指令投递的 API 留着不动：已经设好 Apple Pay「钱包」自动化的人不会坏。小帐本不再教人设置 iPhone 的「电子邮件」自动化，也不再显示连接码。
- 知道转寄地址的人可以寄一封假的「银行邮件」进来，跟连接码外流的后果一样：最多往帐里塞假记录，读不到任何东西。
