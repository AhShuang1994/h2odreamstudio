# 同一期报告重交是更新：建议靠 key 对上，按过的记录永远不删

ADR-0009 让同一期报告重交时整份覆盖：`saveReport` 先删那一期的建议与报告，再插新的。ADR-0010 把建议升级成实验以后，这就会把「做了 / 不做」、开始日、实验结果、判定理由一起删掉。ROUTINE.md 叫 Claude「只交一次」，但修正文、补数据、任务重跑都会再交。2026-10-01 改成：

- **报告留原来的 id**，只换 `period_end`、`body`，记下 `updated_at`。`created_at` 保留第一次交的时间。
- **每条建议有 `key`**：这一期里的固定代号，Claude 自己取（小写英文、数字、连字号）。重交时同一条建议用同一个 key，标题改了也对得上。没带 key 的建议由系统给 `s` + id；迁移 0004 给旧建议都补上，Claude 从 `/reports` 读到后照抄就能接回去。Claude 不能自己起 `s` + 数字的新 key（400），免得接错到别条。
- **对上的建议只换文字与顺序**。状态、`status_at`、`started_on`、`result`、`result_note`、`result_at` 一律不碰。实验已开始（有 `started_on`）的，`hypothesis`、`metric`、`baseline`、`check_weeks` 也不改：到期要判的是当初那个实验，不能事后改题目。
- **没带 key（旧格式）的建议**，只在标题、说明、猜想、指标、基准、检查周数、来源全部一字不差时，才认成某条旧建议。改过一个字就当新的一条。宁可多一条，也不把记录接到错的建议上。
- **新版没提到的旧建议不删**，只标 `retired_at`。实验照算，页面上标「重交后没再提」排在后面。下次再提到同一个 key，标记拿掉。
- 整份写入放在一个 D1 batch 里：中间失败就整批不生效。

## Considered Options

- **按标题对**：标题一改就对不上，记录接不回去；两条同标题也分不清。
- **只禁止重交**（同一期第二次回 409）：最简单，但修正文、补数据就得手动删库，删的时候一样会丢记录。
- **重交时把旧建议的状态按位置（第几条）抄过去**：顺序一换就整批接错，而且错了看不出来。
- **对不上的旧建议直接删**：要求说不能删历史，而且判过的实验是阿爽决定开不开 SEO 服务的依据。

## Consequences

- 没带 key 的请求一改字就会多出一条建议，旧的那条标「没再提」。ROUTINE.md 要 Claude 一定带 key，重交前先读 `/reports` 沿用。
- 建议的数量会随重交慢慢变多（标了 `retired_at` 的不会消失）。一期最多 10 条新建议，量很小，不另做清理。
- 迁移 0004 要在部署新 Worker 之前跑（README「H. 升级」）。迁移只加栏位、补值，不删行。
- 判定理由、基准、猜想照旧只存在 D1，不进 git。
