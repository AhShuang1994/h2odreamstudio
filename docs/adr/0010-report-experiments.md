# 网站报告的建议一律当实验：记猜想与检查期，到期由 Claude 判结果

阿爽打算以后开 SEO 服务，但要先拿自己的网站证明方法有效。ADR-0009 的报告只有「做了 / 不做」，做了之后有没有用，散在每周的文字里，算不出成绩。2026-09-29 讨论后定下：

- **每条建议都是实验**，不分 SEO 与其他。多记五样：`hypothesis`（猜想，要能被数字推翻）、`metric`（只看一个数字）、`baseline`（做之前是多少）、`check_weeks`（几周后检查）、`source`（Claude 提的，或阿爽自己做的）。接口少一样就 400。
- **开始日 = 按「做了」那天**（马来西亚时间），撤销或改成「不做」就清掉开始日与结果。到期 = 开始日 + `check_weeks` 周。
- **阿爽自己做的事也算实验。** Claude 每期读 `docs/seo-action-plan.md` 有日期的 `[x]` 与 git log，没记过的就用 `source: "owner"` 加 `started_on` 记进来，一进来就是「做了」。
- **Claude 判结果**：有效 / 无效 / 看不出，附一两句理由（前后数字、为什么）。拿不准一律「看不出」。阿爽在报告页可以改判。
- **沿用 `suggestions` 表加栏位**，不另开实验表。一条建议从提出、做、到判结果是同一件事，拆两张表只会多一次同步。旧建议没有 `check_weeks`，不算实验。

## Considered Options

- **只改 Claude 的工作说明，结果写在报告文字里**：零代码，但成绩散在每周的文字里，没法算「几个有效」，也没法让阿爽改判。
- **只有 SEO 类建议才算实验**：要多一个分类，而且 WhatsApp、文案类的验证以后的服务也用得到。
- **结果由阿爽自己判**：每个都要她动手，而且她是最想看到「有效」的人。改成 Claude 判、她可以改判。
- **另开 `experiments` 表**：见上面最后一点。

## Consequences

- 同一期报告重交会整份覆盖（ADR-0009），那一期的实验连同结果一起没了。ROUTINE.md 早就规定只交一次，这里不另做保护。（已由 ADR-0011 改掉：重交是更新，实验与结果都保留。）
- 2026-09-25 到 09-29 新版网站没装 GA（PR #186 补回）。碰到这段的 GA 类实验，ROUTINE.md 要 Claude 判「看不出」或把这段排除。
- 小站的数字小，很多实验会是「看不出」。月报在判过的少于 5 个时，要直说还不能下结论。
- 仓库是公开的：猜想、做之前的数字、判定理由都只存在 D1，不进 git。
