# VERIFY —— 三段式校验循环

**目的**:把"看着像不像"变成客观可查的东西。

**铁律**:每轮固定三步,顺序不能变。**不许截完图就闷头开改。**

---

## 一轮的三步

### 第一步 · 写差异

先截图,再并排:

```bash
node "$IMG" shot v1-static.html _review/mine-1.png --w 1440 --full
node "$IMG" compare _src/original.png _review/mine-1.png _review/round-1.png
```

（`$IMG` 的定义见 `SKILL.md` 的「工具脚本的路径」）

**然后先量,再看图。** `rows` 取一列像素,报告纵向的纯色分段 —— 区块边界、内边距、
卡片高度直接就是数字:

```bash
node "$IMG" rows _src/original.png --x 20      # 区块边界(取一列没有内容的边距)
node "$IMG" rows _review/mine-1.png --x 20
node "$IMG" rows _src/original.png --x 300     # 穿过卡片,量卡片高度与内部间距
```

把两边的分段并排,差多少是几,一目了然。**这一步不能省** —— 肉眼看「差不多」的两张图,
量出来可能差 300px。取 x 的诀窍:先取页面边距(如 20)看区块骨架,再取穿过内容的列
(如卡片中心)看内部构成。

然后**按下面 7 项逐条过**,每项写「原图是什么 / 我的是什么」。

> ⛔ 不许写「整体挺接近的,就是有点小差别」。那不是差异清单,是逃避。

**检查顺序是按代价排的 —— 越靠前的错,改起来越贵:**

| # | 查什么 | 为什么排这个位置 |
|---|---|---|
| 1 | **区块顺序和数量** | 少一块 / 多一块 / 顺序错 = 结构性错误,后面全白做 |
| 2 | **内容宽度与左右留白** | 决定整页骨架,改它会连带所有内部间距 |
| 3 | **垂直节奏**(section 间距) | 最影响"高级感"的单项,也最容易整体偏小 |
| 4 | **字号层级**,尤其 h1 : 正文 的比例 | 比例错了每一屏都不对 |
| 5 | **颜色** —— 背景 / 文字 / 强调色分开核 | 局部,但错了很显眼 |
| 6 | **圆角 / 边框 / 阴影** | 局部,决定质感 |
| 7 | **图片位的宽高比** | 局部,但比例错了会挤走周围元素 |

### 第二步 · 写计划

列出**打算改什么、为什么、预期效果**,并给每一项定性:

| 定性 | 判断标准 | 怎么处理 |
|---|---|---|
| **小问题** | 改几个 CSS 值就完事:尺寸、颜色、间距、圆角、字重 | **直接执行**,不用问 |
| **结构性问题** | 要动 DOM 结构、改栅格、整块重写、或推翻某个 section 的判断 | **停下来问用户** |

分不清就当结构性的问。

**为什么要分**:小问题停下来问是浪费用户时间;结构性问题闷头改是浪费两边的时间 —— 万一我对那块的理解本来就错了,改得越多偏得越远。

### 第三步 · 才动手

改完再截图,进下一轮。

---

## 每轮都要打印给用户

差异清单和计划**完整打印在对话里**,同时追加进 `_review/notes.md`:

```markdown
## Round 1

### 差异
1. 区块顺序 —— 一致 ✓
2. 内容宽度 —— 原图 1200px / 我的 1280px ✗
3. 垂直节奏 —— 原图约 96px / 我的 64px ✗
...

### 计划
- [小] 内容宽度 1280 → 1200
- [小] section padding 64 → 96
- [结构] hero 右侧那块我判成了单张图,放大看是 2×2 的图片网格 → **需要确认**

### 改了什么
- 内容宽度、section padding 已改
- hero 右侧待用户确认后再动
```

## 3 轮上限

**最多 3 轮**,然后停下来把剩余差异列给用户。

这条卡的是**说不清来源的差异** —— 到第 4 轮还在「再调调看」,通常意味着某个基础判断
错了,继续微调是在治症状。

剩余差异如果每一条都已经量到、根因明确、改法就是一两个值,那就照实列出来
(哪个元素、差多少、改哪个值),让用户一句话决定改不改。**这不是失败**,
是把决定权交回去 —— 剩下的 10px 值不值得再跑一轮,他比你清楚。

---

## 读对比图的两个坑

**1. 截图尺寸要和原图对齐再比。** 原图是 1440 宽的整页截图,就用 `--w 1440 --full` 截自己的。宽度不同的两张图并排,所有间距看起来都是错的。

**2. 字体没加载完就截图。** Google Fonts 是网络请求,`img.mjs shot` 已经等 `networkidle` 再加 400ms,但首次访问某个字体时可能仍不够。发现字体明显不对(回落成了系统默认字)就重截一次,不要当成"字体选错了"去改 DESIGN.md。
